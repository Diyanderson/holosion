## What this is

Holosion is a set of **standalone, single-file HTML simulators** (UI and text in Brazilian Portuguese) of an aerial real-image apparatus: two concave mirrors facing each other, the upper one with a central hole, that forms a floating real image of an object sitting on the lower mirror — the "Mirage" toy effect. Every simulator is a physics instrument built on **3D vector ray tracing over analytic surfaces**, not an animation.

The **golden rule** governing all of this code (from `prompt-simulador-imagem-aerea.md`): *nothing of the image is drawn — the image is the result of tracing rays.* Never replace a traced quantity with a cosmetic formula. If a sanity check (`verify()`) fails, the tracing core is broken; do not tune constants to mask it.

`prompt-simulador-imagem-aerea.md` is the **canonical specification** — it contains the derived-and-numerically-verified physics, the design rules, the required panels/metrics, the suggested build order (§8), and the sanity checks (§9). Read it before changing any physics. Values marked **verificado** were measured by ray tracing; treat them as regression targets.

## Running / developing

There is **no build system, package manager, test runner, or lint config**. Each `.html` file is fully self-contained except for two CDN dependencies loaded at runtime:
- **Three.js r128** (`cdnjs.../three.min.js`) for the 3D scene
- Google Fonts (Archivo Narrow, IBM Plex Mono/Sans)

To run: open the `.html` file directly in a browser (needs internet for the CDNs; the page shows an error overlay if `THREE` is undefined). There is nothing to compile and no server required.

There are **no automated tests**. Correctness is enforced at runtime by each file's `verify()` function and the `report()`/spec panels, which recompute *predicted vs. measured* from live tracing. When you change the physics core, open the page, trigger `verify()`, and confirm the sanity targets in `prompt-simulador-imagem-aerea.md` §9 (e.g. parabolic pair → axial RMS 0.0000 mm, `m_t = −1`; ellipsoidal pair → axial RMS < 10⁻¹² mm; preset ×1·1cm → 81 points, stretch 1.000).

## Files

The simulators correspond to stages of the build order in the spec, increasing in completeness:

- `simulador-espelhos-concavos.html` — "Banco óptico", 2D meridional ray bench (`traceRay`). The starting point: establish the aberration-free tuning and the degradation cliff.
- `espelhos-3d-foco-ajustavel.html` — "Par elipsoidal", 3D adjustable image height.
- `camera-do-observador.html` — "Câmera do observador", renders what the eye actually receives (`traceFwd`, forward tracing from the eye).
- `objeto-3d-no-leito.html` — **the full/most complete simulator** ("Objeto no leito"): articulated object, occlusion, ring-shaped view cone, ergonomics, source switcher, calibrated presets. Start here for feature work.
- `gravura-especular-no-leito.html` — stage 9 (spec §3.7): engraved specular plate on the bed + on-axis lamp. Grooves are integral curves of `t̂ ∝ ẑ × (ô − L̂)` computed by inverting the relay (`exitThrough`, Newton on the M1 point); the observer camera is per-pixel back-tracing (`backRay`); `runVerify()` checks via forward glint search + `converge()`. Canvas 2D only, no Three.js. Exports the designed grooves (plate frame, scaled ×s — valid only for the whole apparatus and lamp scaled ×s): `exportarGcode()` = single-layer continuous FDM path (round filament ridge → both sides glint, expect the twin); LED-ring mode (`S.anel`, `lampAt(k)`, `copiasAnel`): static plate = N rotated copies, lit LED k selects copy k; HUD counts right vs ghost glints (`CONT`). Profile `fita` = single exact normal per point (two glint conditions, selective); `faceta`/`calha` = range of normals (always glints, so ghosts dominate in ring mode). `exportarStl()` = closed ribbons whose top face has exactly the design normal `n` (for resin + metallizing).
- `nipkow-espiral-no-leito.html` — stage 10 (spec §3.8): programmable volumetric image. A matte wire spiral-staircase rotor on the bed (M spokes, one turn) + addressed light from an on-axis pivot through the hole: `S.fonte` = "vetor" (default; ILDA galvo following DAC points, jump = ⌈Δθ/passo⌉/pps, no settling), "galvo" (point-to-point with settling, worst case) or "dlp" (one binary frame per phase slice). Voxels landing on the same spot of the same spoke share one pulse (`f.mesmo`). Colour: `COR[i]` per voxel (RGB lasers combined into the same beam; matte wire and mirrors are achromatic, so colour does not change the schedule); the camera sums RGB. Animation: `S.tombar` tumbles the object about x (re-conjugates every frame), `S.passeio` walks the eye around inside the view ring; "demonstração" button = coloured torus, galvo vetorial at 120 rps. Object "rosto" = generic line-art face mask (relief h(x,y) seen from above, contour scanlines + features; `curves.tags` drives colours); "resolução máxima" sets npts = curve length / spot (adjacent spots touch). The rotor hub (r < RIN + fio) is a dead zone on the axis: voxels there report "fora do rotor". Hub diameter is `S.eixo` (RIN = eixo/2, set in `agendar()`); near the axis the upper spokes also cross the beam, so keep filled objects ≳0.8 mm off the axis. `planFlash()` falls back to the neighbouring spoke (≤1.6 Δz more depth error, `f.vizinho`) when the nearest one is blocked. `S.cheio` + rosto = filled relief surface (`rostoCheio`, hex grid of pitch ⌀·√3/2 so beam discs cover without gaps, extra samples along steep slopes; colours by `corPele`). "rosto pleno" button: filled face beside a ⌀0.4 axle, ladder fitted to the object depth (Δz ≈ spot), DLP. `S.vortice` orders spokes by a golden step (spoke k at angle k·p mod M, `passoAng()`): fewer blocked beams near the axis, slightly more observer occlusion. `S.meio` = "arame" | "vidro" (K9 ≈ N-BK7 Sellmeier) | "acrilico" (PMMA, Sultanova 2009): the same ladder engraved as microcrack rows inside a transparent cylinder (radius `RB()` = R + borda, flat polished top at `zTopo()` = zMax + topo) that spins with it. Every leg crossing the top face refracts (`refrDir`, `pelaFace` = Snell point on the face by bisection, `noMeio` = air line → line in glass); `objConj` refracts the lobe lines so conjugates are physical in-glass points; `planFlash` aims the galvo at the face point X and stores per-colour lit points `f.Bc` (R/G/B at 638/532/450 nm, dispersion); the camera traces one refracted line per colour; `cortaBloco` drops relay legs that pass through the block; no opaque hub in block mode. `brilhoDe` traces the Fresnel reflection of the beam off the top face through the relay (counts pulses whose glint exits into the view ring). Switching medium re-fits `S.h0` so the object stays centred on the ladder (apparent depth ≈ ÷n). `S.amb` adds the time-averaged haze of unlit spokes under ambient light (Σ fio/2πr). `exportarNuvem("xyz"|"dxf")` writes the engraving point cloud (block frame, x = phase mark, pitch `S.pg`). `runVerify()` also reports dispersion, glint, Gaussian-beam Rayleigh range and the relay Airy radius. Preset "Mirage 9″" (`P.mirage`): the toy as a parabolic pair (f = vertex separation = 80.6 mm, hole ⌀ 62.5 mm, mirrors meet at r ≈ 114 mm; SPIE 9665) built as ellipsoids whose intermediate focus is pushed to ±L (L = 1e9: upper z1 = −L, lower +L) so the existing ellipsoid core is reused; axial conjugate rms ~3e-6 mm. `g.fixo` skips `fitAperture`; `g.field` sets the view-cone field. Buttons `bMir`/`bMirF` (`mirage(spot)`) load it with an unfocused pointer (2 mm spot, M ≈ 6) or a focused one (0.2 mm). Off-axis the toy is not aberration-free (object-space rms ≈ 0.2 mm at r 6 mm, ≈ 1.1 mm at r 15 mm). Camera: gaussian beam profile I ∝ exp(−2r²/w²) and auto-exposure that only lowers gain; voxels are bucketed in an xy×z grid per eye for speed. Each voxel: object-space conjugate by `objConj()` (converge of back-traced lobe rays), spoke + pulse phase by `planFlash()`, passes per frame by `agendar()`. Camera = per-pixel `objLine()` back-trace summed over one rotation, with spoke occlusion (`tapado`). `runVerify()` traces lit points forward through the relay (`imagemDe`) and measures vertical/horizontal parallax by pupil subsets. Panel "Arame e raios em 3D" (`render3D`, state `V3`): orbit view of the rotor at the selected voxel's pulse phase, galvo beam, and the scattered rays from the lit point traced by `trace()` (blocked ones by `tapado`), with their `converge` vs. target distance. The projection above is movable (`S.ox`, `S.oy`, `S.h0`, `S.giro` → `centroImg()`; Shift+drag in the 3D view); moving it re-conjugates every voxel, so off-rotor voxels show up as "fora do rotor" instead of being clamped.

## Shared architecture (inside every `<script>`)

All files share the same plain-JS numeric core (no framework, arrays as vectors `[x,y,z]`). Key functions, consistently named:

- `design()` — from the parameter state `S`, computes the two prolate-ellipsoid geometries. Returns `g = {D, z1, z2, c1,a1,b1, c2,a2,b2, mt, mL, R1,R2, hole, ...}`. `z1` (intermediate focus) is chosen by mode: target magnification `z1 = D·z2/(m·D+z2)`, faithful 1:1, or max-aperture `z1 = D²/(D+z2)`. This is the physics from spec §1.2–1.4; edit here to change optics, not downstream.
- `hitEll(O,d,c,a,b,cap,rmin,rmax)` — analytic ray↔ellipsoid intersection (quadratic), restricted to the `"up"`/`"low"` cap and an annular radius range. The workhorse; used for both mirrors and for occlusion.
- `nEll` / `refl(d,n)` — ellipsoid normal `(Px/b², Py/b², (Pz−c)/a²)` and mirror reflection `d − 2(d·n̂)n̂`.
- `trace(...)` / `traceRay` / `traceFwd` — the **three legs** object→M1→M2→aperture, with physical vignetting: a ray crossing `z = D` outside the hole hits the back of the upper mirror and is barred.
- `pupil()` — annular pupil sampling by golden-angle spiral (`φ = i·2.399963…`).
- `converge(rays)` — image point by **least-squares over exit lines** (`Σ(I − d̂d̂ᵀ)`), not plane intersection — this captures field curvature automatically. Do not replace with a plane hit.
- `viewCone()` / `fitAperture()` — the **ring** (not cone) viewing zone; the hole opens a blind spot above the image. Aperture/hole/lower-mirror are auto-sized by iterating hole ↔ lower mirror (~3×) so the two mirrors need not share a diameter (forcing equal diameters drops transmission to ~58%).
- `buildFigure()` / occlusion — the object is an **articulated union of spheres**; the same representation draws, samples, and tests occlusion so what you see equals what is traced.
- `verify()` — runs the spec's sanity checks against live tracing.

In `objeto-3d-no-leito.html`, Three.js code lives after the numeric core (`scene`, `gMirror`/`gRay`/`gObj`/`gImg`/... groups, custom orbit camera). Rebuild scope is split for performance (spec §4.7): `buildOptics()` only when mirror params change; the image rebuilds on object rotation; a draft pass runs during drag, a fine pass (~170 ms) on release. State lives in a single `S` object; `bind(...)` wires sliders to it.
